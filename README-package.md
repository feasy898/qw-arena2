# 智能选购顾问 Agent — 架构说明

本文件随提交包分发。目标读者：初次接触本代码库的工程师与评审者。每条设计都可在
包内源码复核。

## 1. 任务与产物

输入目录 = 1 份用户描述 + 五源商品资料（货架快照 / 媒体报道 / 第三方实测 / 用户反馈 /
品牌官网）。一次运行在输出目录产出且仅产出三份 Markdown：

- `user_profile.md`（用户画像）／`product_list.md`（产品属性）／`recommendation.md`（消费推荐报告）

内容纪律：一切取值可回溯到输入文件；输入未载明的字段一律写「待核验 / 未提供」，
不编造、不用间接信息外推。

## 2. 主链：强模型单次直出（`src/advisor_pipeline.py`）

- 输入全集约 16KB，远低于上下文上限：单次调用即可同时看到全部产品与全部来源——
  跨产品比较、来源间矛盾识别在同一个注意力上下文内完成，不需要多阶段拼接
  （拼接式抽取在字段归并口径上不增益，反而引入过程性文本与字段遗漏）。
- 后处理是确定性规则（同文件内 postprocess）：把过程性措辞与模板残留归一为
  「待核验」、清除残留角标。只改表达，不改语义，不做任何内容生成。
- 失败语义：任何异常（网关不通 / 模型全挂 / 解析失败）原样抛出，交给入口的防线层
  与降级链，主链自身不做静默兜底。

## 3. 模型选型与降级阶梯

- 仅调用官方白名单内文本模型，经 `OPENAI_BASE_URL`（以 /v1 结尾）的 OpenAI 兼容
  chat 接口调用；密钥仅从环境变量 `DASHSCOPE_API_KEY` 读取，不进代码、日志、文档。
- 主选 `qwen3.8-max`，兜底序列经 `config.example.json` 的 advisor 段配置；
  直出路径对限流类状态（429/5xx）原地指数退避至多 2 次再切换下一模型，
  整个直出路径受进程级死线（1500s，为回退链预留 ≥300s）钳制，死线临近
  不再发起新调用；多阶段降级链经模型网关层另有指数退避。
  advisor 段模型在装载时即做白名单校验，白名单外模型被剔除并降级为默认选型。
- 直出路径失败 / 无 Key / mock 环境：回退 `src/pipeline.py` 多阶段确定性降级链，
  降级阶序只升不降，禁止用「丢部分产品」降级；目标唯一——任何环境下产出
  结构完整、可解析的三份文档。

## 4. 不死鸟防线（`agent.py`，三层）

1. 正常路径：sys.path 自举后引用主链，rc==0 → 退出 0；
2. 主链返回非 0：只对缺产物的候选位置补写三份极简模板，不覆盖已有真实产物，
   然后退出 0；
3. import / 启动失败：在所有候选位置写极简模板（诊断标记只含异常类型与摘要，
   不含用户资料），异常写 stderr 与 `AGENT_LOG_DIR/agent.log`，然后退出 0。

背景：平台沙箱的启动期故障（import 失败、依赖缺失、参数解析异常）发生在一切
进程内降级之前，一旦发生即整场无产物。防线保证：**「三份产物 + 退出码 0」恒成立**。`agent.py` 自身只 import 标准库，防线层不依赖任何第三方包。

## 5. 提交包布局（双布局）

官方文档同时存在「产物所在目录须命名为 agent」与「入口文件必须位于根目录」两条
表述。同份内容写入 zip 内 `agent/<rel>` 与 `<rel>` 两处，两种 runner 调用约定都
命中；两种 runner 调用约定任一成立即可正常运行。

## 6. 镜像输出（多点写入）

平台检查产物计数的目录与文档示例路径不完全一致，单点写入可能被判定
「产物文件数量与任务要求不符」。因此主输出之外，三份产物镜像到
候选位置——指令中的输出路径、输入目录同级 output、平台标准输出目录、当前目录
output。任一位置被检查都能数到恰好 3 个标准命名文件；候选路径全部运行时构造，
源码不含绝对路径字面量。镜像写入失败不影响主流程。

## 7. 包内 mock 网关夹具（`tests/fixtures/gateway/responses.json`）

用于官方本地验证工具在无 Key / `QW_FORCE_MOCK=1` 环境离线运行：
网关 mock 模式按 mock_key 从夹具取确定性应答，mock_key 缺失必须抛错，
禁止静默兜底。线上真实模式不读该夹具。

## 8. 资源纪律

- 单次运行硬截止 1800s（直出路径自限 1500s，留 300s 给回退链），内存 ≤ 4GB；
- 网络仅访问平台模型服务，无任何外部检索；
- 运行遥测（选用模型 / 耗时 / token 用量 / 降级原因）写入 `AGENT_LOG_DIR/agent.log`。

## 9. 出厂质检（`src/self_check.py`）

主链在写盘之后、镜像之前对三份产物跑一遍**出厂质检**：按公开任务规格逐项自检，
不过则定点修复或回退。定位是**规格符合性质检（quality gate）**——本机制不针对
评分器，仅保证交付物符合任务说明的硬性要求。

- 检查项 = 确定性、无网、纯标准库规则（`src/self_check.py` 为单一事实源；开发仓
  的确定性评分器 `tools/deterministic_judge.py` 复用同一套规则函数）：文件命名、
  表格可解析、画像 7 字段组、产品 5 字段组与全产品表结构一致、推荐表恰 3 行与
  综合结论、未选原因覆盖、过程性措辞/模板残留、售价取货架展示价、推荐 ID 存在于
  产品表且售价 ≤ 预算×1.1、画像硬字段与用户描述的数值归一/关键词比对（年龄
  「30岁」≡「30」、预算「约3000元」≡3000；品牌/品类按关键词包含；「现有主要
  设备」不得含用户描述中旧设备转折语之后提及的品牌名）。全部判定依据在运行时
  从输入资料推导，包内不含任何样例数据的具体取值；开发仓评分器另持有一份
  基于官方公开样例的金标准回归锁（开发期专用，经 golden 注入参数挂载，
  不随包分发、不参与出厂质检）。
- 每条未过项输出为单条可执行修正指令（`failed_atoms: {doc, rule, message}`）。
  主链闭环：全过 → 照常镜像、返回 0；不过 → 在预算门限内**恰好重试 1 次**
  （仅主选模型，prompt 尾部逐项注入失败清单，要求逐项修正且不复现）；重试后仍
  不过 → 交付缺陷最少的历史最优版本（写盘并镜像），返回 0，失败清单写入 stderr
  与 `AGENT_LOG_DIR/agent.log`——三份文档齐全时质检不过不构成回退降级链的
  理由。§3 的「不重试同一模型」指模型调用失败（网关/HTTP）的切换阶梯；质检
  重试是唯一例外且仅一次、仅主选模型。
- 采样参数随质检闭环收紧：temperature 0.05、seed=42、top_p=0.9（OpenAI 兼容
  字段直传），降低逐次波动、保证重试可比。
- 质检门自身不可用或异常时不阻断主链（fail-open，与镜像「绝不影响主结果」同一
  纪律）；重试受两重预算约束：估算门限（全局剩余 − 上次调用×1.2 ≥ 90s）与
  进程级死线（死线临近不再发起任何调用），保证任何路径都给回退链与写盘收尾
  留出余量。

### 9.1 全局时钟与墙钟纪律（0.7.6）

平台单次执行硬限 1800s（超时任务失败）。本版起全进程共用一份时间源
（`src/timekeeper.py`，纯标准库）：

- **进程级全局时钟**：总预算 = 平台硬限 − 300s 安全垫（默认 1500s，
  `QW_AGENT_BUDGET_S` 可收紧），自进程起点计时；直出链、降级链、网关的
  一切死线/预算都从同一起点推算——直出链移交降级链时，降级链继承已耗时间
  而非新开口径，任何路径组合的总墙钟都不越过全局死线；
- **单次调用墙钟封顶**：LLM 单次调用以守护线程按墙钟计时（600s 上限，逐次
  再被全局剩余钳制），到点即按失败换候选——socket 读超时对慢流式响应
  （字节间隔小于读超时）无效，墙钟是唯一真实上限；
- **移交预留**：直出链发起新调用前，为降级链强制预留 150s（确定性产出 +
  写盘 + 镜像），保证「直出失败 → 降级链」永远跑得完；
- 探测矩阵在软剩余 <45s 时整体跳过，不挤占确定性产出的收尾窗口。
